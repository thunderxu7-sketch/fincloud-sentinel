03 / GOVERNED AI DELIVERY

AI 落地，不是接一个聊天框。

企业真正需要的是：回答有依据、输入先脱敏、提示注入被限制、质量可以回归、低置信度能降级，高影响动作必须由人确认。

一句话先懂受控 AI 的目标不是“回答得像人”，而是“只看该看的证据、不给无依据结论、越权动作做不了、质量下降时能被发现并安全降级”。
01 / 先用生活例子理解

把 AI 想成急诊室里的住院医师助手。

它可以快速找病例和操作手册、整理症状、给出建议，但不能隐藏证据、不能泄露患者隐私，更不能未经主治医生确认就执行高风险治疗。

生活类比

助手可以提速，责任不能外包

可靠的助手不是凭记忆“像懂一样回答”，而是先找到最新指南，标出依据和不确定性；隐私先处理；遇到危险指令要拒绝；真正改变患者状态的动作由医生签字。

查最新诊疗指南→

RAG：先检索企业知识，再生成带来源的回答。

遮盖患者隐私→

脱敏：令牌、密码、身份证明等在进入模型前被移除。

药物禁忌和权限→

Guardrails：检测注入、限制工具、约束输出和动作风险。

定期病例考试→

评测：固定用例持续检查检索、引用、安全、时延和降级。

主治医生签字→

人工确认：对资金、权限和生产配置变更保留责任门禁。

02 / 五个核心能力

从“能回答”走到“可治理”。

企业 AI 的技术主线不是模型越大越好，而是知识、数据、策略、质量和责任能够闭环。

01

RAG 检索增强生成

先把问题变成检索查询，召回相关 Runbook 或业务文档，再把片段和来源交给生成步骤。答案必须能指回原文。

question → retrieve → rerank
→ grounded answer + citations
02

数据脱敏 Redaction

采用数据最小化原则，只提供完成任务所需字段。API key、token、密码、个人数据和密钥模式在日志与模型输入前清除。

raw evidence → policy filter
→ [REDACTED] → model
03

Guardrails 护栏

输入侧检测提示注入，检索侧限制知识范围，工具侧使用白名单，输出侧检查引用和敏感信息，动作侧按风险分类。

input / retrieval / output / tool
four boundaries, not one prompt
04

评测 Evaluation

离线回归检查检索命中、引用完整性、答案正确性和安全策略；线上监控时延、错误率、拒答率、人工接管率与漂移。

golden cases + adversarial cases
quality gate before release
05

人工确认 Human-in-the-loop

只读查询可以自动执行；修改配置、暂停资金通道等高影响动作必须展示依据、影响范围和可回滚方案，由授权人员确认。

READ_ONLY → auto
MUTATING / FINANCIAL → approve
06

安全降级 Fallback

模型超时、置信度不足或评测不达标时，退回确定性规则、只读查询或人工流程，而不是用不可靠结果继续自动化。

model unavailable
→ deterministic safe mode
03 / 一次事故调查如何完成

先收集证据，再建议动作；建议与执行分离。

STEP 01

接收最小上下文

事故编号、严重级别、指标、脱敏日志和交易编号进入调查请求。

STEP 02

检索知识

从版本化 Runbook 中召回最相关片段，保留文件名、摘录和得分。

STEP 03

生成有据诊断

将事实、假设、置信度与证据分开；证据不足时明确说“不足”。

STEP 04

动作策略判定

只读工具可自动调用；越权、修改或资金动作被强制标为需要审批。

STEP 05

人审与审计

操作员查看引用和影响，明确批准后才执行，并记录谁在何时做了什么。

04 / 五类质量问题如何防

模型问题不能只靠“提示词写好一点”。

风险表现控制验证指标
幻觉没有证据却给出确定结论强制引用、证据不足拒答、确定性降级Groundedness、引用准确率
提示注入文档或用户要求绕过策略输入检测、指令与数据隔离、工具白名单攻击用例通过率
敏感信息泄露日志或输出出现 token、密码、个人信息输入前脱敏、输出扫描、最小权限泄露用例为 0
模型退化升级后召回、答案或时延变差版本化模型/提示/知识库，离线评测守门质量阈值、P95 时延
越权执行AI 直接修改生产或资金状态动作分级、策略引擎、人工审批与审计未审批高风险动作 = 0
05 / FINCLOUD SENTINEL 中如何落地

先证明治理闭环，再替换成真实模型。

当前实现故意使用确定性诊断和词法检索，便于离线测试每条安全规则；生产方案可以替换向量检索与模型推理，但审批和证据契约保持不变。

KNOWLEDGE

版本化 Runbook

链上确认延迟、重复事件、账本对账、模型超时等知识以 Markdown 入库。

RETRIEVAL

可重复词法检索

根据事故标题、症状、指标和日志召回片段，输出 source、excerpt 与 score。

REDACTION

密钥模式脱敏

API key、token、password 及常见云访问键在分析和引用前替换。

GUARDRAIL

注入与工具策略

检测绕过指令；只读工具白名单自动放行，其余动作一律要求审批。

EVAL

4/4 固定评测

每个事故必须命中预期 Runbook、有非空证据，且高风险动作不能绕过审批。

OBSERVE

FastAPI 与指标

调查 API 暴露健康、就绪与 Prometheus 请求量/时延指标。

边界说明Pages 上的调查助手明确标注为离线确定性模式，不冒充在线 LLM；生产接入百炼、PAI-EAS 或其他模型后，还需补充向量库、模型版本、提示模板、线上评测、成本与合规控制。
06 / 面试可以直接这样讲

90 秒口述版本。

“我把企业 AI 落地拆成五个治理环节。第一是 RAG，回答前先检索版本化知识并保留引用；第二是脱敏，敏感字段在进入模型前最小化；第三是 Guardrails，分别约束输入、检索、输出和工具；第四是评测，用固定和对抗用例守住检索、引用、安全与时延阈值；第五是人工确认，只读动作可以自动执行，修改和资金类动作必须审批。我的项目用确定性检索和诊断先把这些契约做成可测试闭环，未来替换真实模型时，证据、降级和审批边界仍然不变。”
表达结构

重点不是说会用多少模型，而是能把知识、数据、安全、质量和责任完整串起来。

07 / 面试官继续追问

四个高频问题。

RAG 为什么仍然会幻觉？

检索可能召回错误或过期内容，模型也可能忽略证据。因此要做文档版本治理、召回与重排评测、引用校验、证据不足拒答，并把事实与推断分开。

Guardrails 是不是一段 system prompt？

不是。提示词只是软约束。可靠护栏还包括数据过滤、身份权限、工具白名单、结构化输出校验、动作策略、速率限制和审计，关键控制必须在模型之外执行。

评测应该看哪些指标？

离线看召回率、引用准确率、答案正确性、安全攻击通过率；线上看时延、错误率、拒答率、人工接管率、用户反馈和成本。高风险场景还要看未审批动作是否为零。

为什么不让 AI 自动处理事故？

可以自动完成低风险只读查询和证据整理，但事故中的错误动作可能扩大影响。建议与执行分离、最小权限、可回滚和人工审批能让责任清晰。

08 / 不要这样说

四个常见 AI 包装误区。

!

“接入大模型就有智能运维”

没有知识、遥测、工具权限、评测和流程，模型只是新的不确定接口。

!

“用了 RAG 就不会幻觉”

RAG 降低而非消除幻觉，仍需引用校验、拒答和回归评测。

!

“数据都在内网所以不用脱敏”

内部泄露、日志扩散和供应链风险仍存在，应坚持最小数据和分级权限。

!

“人工确认会影响自动化效率”

只对高影响动作保留门禁，低风险只读步骤仍可自动化，整体反而更可运营。
